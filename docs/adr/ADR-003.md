# ADR-003: Enum Nativo JoinType para Junções Relacionais

> Status: Aceito (retroativo) | Data: 2026-10-13
> Decisores: Heliomar P. Marques | Substitui: n/a
> Relacionados: Commit a0bbacf, src/LinqPHP.php:L7-L13

## Contexto e forças
A operação relacional de `join` no `LinqPHP` suporta múltiplos tipos de junção (INNER, LEFT, RIGHT, FULL). Inicialmente, era comum em ecossistemas legados aceitar strings literais como parâmetros de configuração (por exemplo, `join($dataset, 'LEFT', $keys)`).

No entanto, o uso de strings literais apresenta desvantagens críticas:
1. Suscetibilidade a erros de digitação (`typos`) ou variações de caixa (como `'left'`, `'INNER '`) que só explodem em tempo de execução.
2. Necessidade de código defensivo redundante para normalizar e validar strings com exceções manuais.
3. Ausência de suporte para autocompletar na IDE e verificação em análise estática.

Com o requisito mínimo estabelecido em PHP 8.1+, a linguagem oferece suporte de primeira classe a Enums tipados e backed enums.

## Critérios de decisão
Segurança de tipo estrita (type-safety), eliminação de validações defensivas repetitivas, excelente experiência de desenvolvimento (DX) com autocompletar em IDEs.

## Decisão
Criar o enum backed nativo `enum JoinType: string` dentro do namespace `HeliomarPM\LinqPHP`:
- `JoinType::INNER = 'INNER'`
- `JoinType::LEFT = 'LEFT'`
- `JoinType::RIGHT = 'RIGHT'`
- `JoinType::FULL = 'FULL'`

A assinatura do método `join()` foi atualizada para exigir obrigatoriamente a instância do Enum:
```php
public function join(array $joinData, JoinType $joinType, array $relatedFields): self
```

## Alternativas avaliadas

| Opção | Prós | Contras |
| :--- | :--- | :--- |
| Strings literais com validação em runtime | Compatibilidade com códigos antigos | Erros só detectados em execução; sem auxílio da IDE |
| Constantes de classe (`LinqPHP::JOIN_INNER`) | Compatível com PHP 7.x | Não possui tipagem forte no parâmetro do método; aceita qualquer string ou inteiro arbitrário |
| **Enum nativo `JoinType: string` (escolhida)** | Tipagem rigorosa em tempo de análise estática, autocomplete nativo, código moderno e legível | Requer PHP >= 8.1; quebrou compatibilidade com chamadas baseadas em strings literais |

## Consequências
- Positivas: validação garantida pelo interpretador do PHP antes da execução do algoritmo de junção; documentação explícita na assinatura do método; facilidade imediata de uso na IDE.
- Negativas: alteração com quebra de compatibilidade (breaking change retroativa) que exigiu atualização de chamadas nos testes e suítes de benchmark (registrada no commit `a0bbacf`).
